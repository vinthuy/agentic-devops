# Design

## Context

见 `proposal.md` 的 Why。当前编排器是唯一会转移任务状态的组件。审批命令、审查结论、审批超时和 L 级拒绝编码都已经存在。GitHub 只用于导入 Issue 正文、推送分支、创建草稿 PR 和查询 CI。

## Goals / Non-Goals

**Goals:**

- GitHub 上的人为动作映射到已有命令，状态真源仍是本地任务。
- 规划前能读取仓库，但不能在审批前写入。
- L 级的每一段都重新经过 M 级审批门。

**Non-Goals:**

- 不把评论正文、标签或 `AGENTS.md` 交给模型当作新需求。
- 不在本进程内监听 Webhook 或运行定时循环。
- 不在这一批支持每个角色使用不同的 `base_url` 或 API key。

## Decisions

1. **斜线命令是投影。** 评论首词只接受 `/approve`、`/reject`、`/replan`。其余文本丢弃。标签只创建任务，不表示批准。备选是把整段评论送给模型，或用标签直接进入编码。前者扩大提示注入，后者没有驳回理由。
2. **先转移状态，再发表 PR review。** 发表失败记事件，不回滚。备选是以 GitHub review 状态决定是否回到编码。那样一次网络失败会把已经做出的打回变成没有审查。
3. **`sweep` 不调用领取任务。** 它与 `run` 共用到期处理函数。调度放在外部 cron。备选是在进程内循环，那会把 CLI 变成服务。
4. **检索只走读路径策略。** 上限为 8 次读取、单次 4000 字符、合计 16000 字符。无命中且无法定位时，计划必须是待澄清。备选是把编码工具整套交给规划器，那样规划阶段可以在审批前改仓库。
5. **角色模型缺省回退到 `model`。** 缺单价沿用现有告警，不新增一条按免费记账的路径。
6. **`AGENTS.md` 只注入规划与审查。** 超过 8000 字符时保留前部并标明截断。策略引擎继续拒绝被文件文字放宽的路径、命令和预算。
7. **L 级只创建下一段。** 子任务带 `parent_task_id`，自己停在审批门。父任务不进入编码。上一段被拒绝或取消后不再创建后续段。备选是一次批准整份拆分，那等于把 L 级审批缩成一次点头。
8. **CI 差异基准不替换用户仓库的 workflow。** 只有专门回答「CI 能否发现本地发现不了的问题」的剧本才必须多一条检查。

## Risks / Trade-offs

- [评论命令与 CLI 规则分叉] → 评论路径调用现有 approve/reject 函数，不复制转移表。
- [重复投递同一评论造成两次编码] → 已应用的 GitHub comment id 写入事件，再次见到则直接返回。
- [检索把不可信文件内容送进规划] → 摘录放在不可信数据边界内，并写明路径。
- [拆段后父任务停在待人工，看起来像失败] → 负载写明 `l_split` 和当前子任务 id，与拆分失败区分开。

## Migration Plan

没有已发布的数据需要迁移。`parent_task_id` 对旧库补可空列，现有行保持空。未配置 `roles` 的 `models.yaml` 行为与现在相同。

## Open Questions

无。未决定的厂商多 key 和进程内 Webhook 服务明确排除在本变更之外。
